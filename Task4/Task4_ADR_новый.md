**Логика решения**

Решение в том, чтобы и внутренний и партнёрский кол-центр могли консультировать клиентов по актуальным ставкам, но при этом они получают ставки по-разному, и мы не заводим новый источник данных.

Внутренний кол-центр подключаем к сервису ставок по API. Система кол-центра при звонке читает актуальные ставки прямо из сервиса ставок, поэтому менеджер всегда видит свежие значения. Ставки берём из сервиса ставок, а не из АБС, чтобы увеличение звонков не создавало нагрузку на перегруженную базу АБС (требование 6). Это заложили еще с прошлого ADR.

Партнёрский кол-центр внешний и не может дёргать наш API, поэтому для него добавляем в сервис ставок отдельный компонент, экспортёр ставок. Он по расписанию читает актуальные ставки из базы, формирует файл и выкладывает его на SFTP. Партнёр забирает файл и загружает в свою систему. SFTP шифрует передачу и открывает партнёру доступ только к файлу со ставками, а не к API и внутренним данным банка (требования 3, 4, 5). Так как ставки обновляются каждый день, экспорт запускаем по расписанию, минимум раз в день после обновления ставок бэк-офисом (требование 2).

Ключевой момент это кол-центры берут ставки из одного сервиса ставок. API отдаёт их банковскому кол-центру, экспортёр кладёт те же данные в файл для партнёра. Поэтому во всех кол-центрах ставки одинаковые и совпадают (требования 1 и 7). Мы просто добавляем к сервису ставок второй способ выдачи.

### **Альтернативы**
Опишите здесь наиболее важные альтернативные решения.

1. Дать партнёру прямой доступ к API или базе сервиса ставок. Отклонили, потому что партнёр сам сообщил, что не может делать API-вызовы, и открывать кому-то извне доступ внутрь банка небезопасно.
2. Отправлять ставки партнёру вручную по почте. Отклонили, потому что это ручной процесс которые требует ежедневного действия и возможны ошибки из-за человеческого фактора.
3. Внутренний кол-центр читает ставки напрямую из АБС. Отклонили, потому что база АБС перегружена.

**Недостатки, ограничения, риски**

Подробно опишите здесь недостатки, ограничения и риски выбранного решения.

1. Файл у партнёра обновляется по расписанию, поэтому между изменением ставки в банке и загрузкой нового файла есть задержка. Партнер может консультировать по устаревшим данным. Частоту экспорта нужно согласовать.
2. Файловый обмен через SFTP нужно настроить и поддерживать, это отдельная задача.
3. Формат файла становится контрактом с внешним колл-центром. Любое изменение формата надо согласовывать с ним.
